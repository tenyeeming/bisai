# 測試

```bash
cd D:\穴道按摩\比賽專區\demo網站
npm install     # 只需要做一次，裝 jsdom
npm test
```

`npm test` 會跑完三支並只印失敗細節。要看每一項就用 `npm run test:verbose`。
也可以單獨跑：`node tests/check.js`。

---

## 三支各自在管什麼

| 檔案 | 需要套件 | 在測什麼 |
|---|---|---|
| `check.js` | 無 | **靜態檢查**：讀原始碼比對，不執行網站 |
| `e2e.js` | jsdom | **端對端**：載入真的 HTML、把 MediaPipe 換成假的，走完整個流程 |
| `mirror.js` | jsdom | **鏡像繪製**：攔截 canvas 呼叫，驗證前鏡頭的翻轉邏輯 |

### `check.js` — 靜態檢查

專抓「拆成多檔之後最容易踩、但肉眼看不出來」的問題：

- **頂層宣告不得重複** —— 所有 `.js` 共用同一個全域作用域，兩支各宣告一次 `let x` 會整站白畫面
- **每頁註冊的 `id="page-X"` 要跟頁名一致**，否則 `showPage()` 找不到頁
- **inline `onclick` 呼叫的函式都要存在**、`getElementById` 的目標都要在某頁的 HTML 裡
- **i18n 中英 key 成對**、`data-i18n` / `t()` 用到的 key 都有翻譯、**沒有沒人用的孤兒 key**
- **26 隻小人的 SVG 檔齊全**、沒有兩穴共用、也沒有多餘的孤兒檔
- **程式碼裡不能出現 `fetch` / `XMLHttpRequest`** —— 這兩個在 `file://` 會被 CORS 擋掉，
  一旦有人加回來，「雙擊就能開」這件事就壞了

### `e2e.js` — 端對端

把 `<script src>` 內聯、`Hands`/`Camera` 換成假的，然後真的操作 DOM 走一遍：

症狀 → 推薦 → 部位切換 → 勾選 → 認穴 → 定位 → 按摩（左手一輪、右手一輪）→ 完成 → 圖冊 → 個人

順便驗這些容易回歸的行為：計時只在 `onTarget` 為真時前進、換手提示、提早結束不寫紀錄、
切語言不會清掉勾到一半的穴道、連續天數斷了歸零、相機生命週期、急症 119 紅框。

> ⚠️ 這支刻意把 `window.fetch` 設成一律 reject，等於在模擬 `file://` 環境。

### `mirror.js` — 鏡像繪製

從專案根目錄的 `測試記錄/*.json` 撈**真實的 21 點 landmark**，餵進 `onHandsResults`，
用假的 canvas context 錄下每一個繪圖呼叫，驗證：

- 影像與信心圓盤在**翻轉狀態下**畫（圓盤是多邊形，整組頂點都得翻）
- 穴名**不在**翻轉狀態下畫 → 不會變成反字
- 前後鏡頭的 x 相加正好等於畫布寬（鏡像是精確的，不是目測的）
- **原始 landmark 沒有被就地改動** —— 定位公式吃的還是原值

## 加測試時的注意事項

- 斷言一律用 `ok(條件, '訊息')`，訊息寫**具體現象**不要寫「應該正確」。
  失敗時 `run.js` 只會印那一行，訊息不具體就等於沒訊息。
- 測到數值時把實際值放進訊息（例：`` `對準後計時開始前進（5000ms → ${remain}ms）` ``），
  之後回頭看才知道當時是差多少。
- `state` 這類頂層 `let` 不會掛在 `window` 上（它們在全域語彙環境），
  要讀寫得用 `w.eval('state.history')`。
